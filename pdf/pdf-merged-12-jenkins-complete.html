01 / Why Jenkins

  • WHAT — open-source automation server: pipelines as code, 1,800+ plugins, controller + agents. Self-hosted, free, runs anywhere.
  • WHY — your data/secrets on your infra; reaches air-gapped networks and special hardware; no per-minute billing.

Topology

05

Picking up from the Domain map — we now examine the controller–agent topology that every pipeline, agent, and credential later plugs into.

01 / The Three Parts

  • Controller — holds config (JENKINS_HOME), queue, history, UI/API, credentials. Runs no builds in production.
  • Agent — a machine offering executors: numbered slots, one build each.
  • Remoting — the channel shipping work out. Inbound = agent dials out (survives NAT); SSH = controller dials in (flat networks).

02 / What Lives in JENKINS_HOME

PathHolds
jobs/Job configs + build history
workspace/Checked-out code (rebuildable, deletable)
credentials.xml + secrets/Encrypted secrets — back up securely
config.xmlGlobal configuration

Failures & Handoff

06

05 / Failure Modes

  • Disk fills with old builds → UI freezes; fix with build discarders + log rotation.
  • Everything pinned to built-in node → single contention point; fix with labeled agents.
  • Clock skew → signatures/webhooks fail; run NTP everywhere.
Q1 Controller vs agent responsibilities?
Controller schedules, serves, stores. Agents execute — nothing else.

06 / Handoff

Topology understood — now build one. Continue in Jenkins Setup.

🎓 EXAMTopology in one breath: the controller schedules, serves and stores (JENKINS_HOME: jobs/, workspace/, credentials.xml + secrets/, config.xml) and runs zero builds; agents offer executors, one build per slot, reached by inbound remoting (agent dials out, survives NAT) or SSH (controller dials in). Classic failures: disk full of old builds, everything pinned to the built-in node, clock skew.

Agent Wiring

15

03 / Connection & Trust

  • Inbound — agent dials out via WebSocket; survives NAT, needs port 50000.
  • SSH — controller dials in; simple on flat networks, needs port 22 + credential.
  • Ephemeral wins — pristine container per run kills "works on my machine" and tool drift.
TRUST BOUNDARY

Never run untrusted fork PRs on permanent agents holding deploy credentials. Forks get isolated, credential-free agents — a malicious workflow otherwise owns your box.

  • Label typo → queue forever; check Executor Status.
  • Too many executors per CPU → starvation.

04 / Handoff

Agents run the work — next they need secrets. Continue in Jenkins Credentials.

🎓 EXAMAgents in one breath: permanent nodes for special hardware, Docker cloud containers per build as the Linux default, Kubernetes pods per build for bursty CI — matched by labels (capability tags, linux && docker) while an executor is one build slot sized ~1 per 1–2 cores; ephemeral wins because a pristine container kills tool drift, and fork PRs run only on isolated, credential-free agents.

Bindings

20

02 / Binding in Practice

withCredentials([usernamePassword(
  credentialsId: 'registry-creds',
  usernameVariable: 'U', passwordVariable: 'P')]) {
  sh 'echo "$P" | docker login registry -u "$U" --password-stdin' }
# Jenkins masks $U/$P in console output automatically

03 / Failure Modes

  • Secret echoed or baked into an image layer → treat as compromised, rotate immediately.
  • Wrong scope (System-only in pipeline) → "credentials not found"; move to Global.
  • Duplicate IDs → ambiguous resolution; keep IDs unique (github-acme-app-token).
LEAK = ROTATE

Masking is a backstop, not a guarantee. Any secret that touched a log, layer, or chat is compromised — replace by ID, zero Jenkinsfile changes.

03 / Multibranch = PR Gates

Multibranch scans the repo, builds each branch/PR Jenkinsfile independently, reports status to GitHub checks. Branch deleted → job auto-removed. No hand-wired jobs per branch, ever.

  • Duplicates → webhook + polling both on; disable polling.

Trust

29

02 / Agent-to-Controller Distrust

  • Builds execute attacker-influenced code — default deny on Agent → Controller access.
  • Ephemeral agents: a compromised container dies with the build.
  • Fork PRs → isolated, credential-free agents. Never shared permanent ones.

03 / Secrets & Updates

  • Secrets only via bindings; set +x around manual handling; TLS-only admin.
  • Rotate by ID replacement; deprovision SSO, don't rely on memory.
  • CVEs cluster in plugins: staging validates → snapshot → production.
IF SECRETS LEAK

JENKINS_HOME/secrets decrypts the whole store. Its exposure = everything is compromised. Rotate all of it.

Q3 Why are PR builds a trust boundary?
PR contents are attacker-influenced code running on your agents — isolate execution and scope credentials.

  • First red line = effect; scroll up for the cause (exit code, Groovy stack).
  • Replay button re-runs edited pipelines without pushing commits.
  • Wipe workspace + rebuild separates dirty-workspace flakes from real failures.

03 / Sandbox & Recovery

SANDBOX untrusted scripts run allowlisted only; beyond that needs Script Approval. Prefer allowlisted steps — each approval is future maintenance.
RECOVERY — bad config? Restore config.xml + Reload Configuration (no restart). Disaster? Restore JENKINS_HOME backup to a fresh pinned image, replay the smoke pipeline.

04 / Handoff

Jenkins domain complete — now meet the sibling implementation. Continue in GitHub Actions: hosted runners, YAML, zero infrastructure.

🎓 EXAMTroubleshooting in one breath: diagnose in order — stuck in queue → labels/executors, No such DSL method → owning plugin, command not found → tool on that agent, clone failures → credential scope, silent webhooks → hook log, frozen controller → disk/heap; the first red line is the effect, scroll up for the cause, replay without pushing, wipe the workspace to separate flakes from failures, prefer allowlisted steps over approvals, and recover via config.xml + Reload or a full JENKINS_HOME restore onto a pinned image plus the smoke pipeline.

🎤 Concept Questions — Distilled Answers

37
Q1 Controller vs agent responsibilities?
Controller schedules, serves and stores. Agents execute — nothing else.
Q2 Declarative vs Scripted — when each?
Declarative for 95%: validated, readable. Scripted for dynamic stages and advanced flow.
Q3 Label vs executor?
Label is a capability tag matching jobs to agents. Executor is one build slot.
Q4 Why set built-in executors to 0?
So no build ever lands on the controller — it is a single contention point, not a worker.
Q5 A secret touched a log. What now?
Treat as compromised and rotate by ID immediately. Masking is a backstop, not a guarantee.
Q6 Multibranch vs hand-wired jobs?
Multibranch auto-discovers branches/PRs, gates each, reports checks, removes dead branches. Never hand-wire.
Q7 Socket mount vs DinD?
Socket is fast for trusted teams but shares the daemon. DinD isolates untrusted builds.
Q8 Rebuild-a-controller drill order?
Pinned image → plugins → JCasC → secrets → backup restore → smoke pipeline. Secrets break first.
