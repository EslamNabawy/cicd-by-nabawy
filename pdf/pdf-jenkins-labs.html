Lab 01

Webhook → Build
01
GITHUB WEBHOOK TRIGGER

A push should be enough. One commit, one webhook, one build — no human clicking Build Now. This lab removes the manual step between GitHub and Jenkins.

01 / What This Lab Proves

PROOF — Jenkins reacts to Git events via /github-webhook/ and GitHub hook trigger for GITScm polling. Reachability + credentials + branch match are the only three things that can break it.

02 / Architecture

GITHUBpush to branch
→
WEBHOOK/github-webhook/
→
JENKINSBuild Triggers

GitHub delivers a POST to Jenkins. Jenkins matches the repo + branch, checks out with stored PAT, and starts the job. If any hop is unreachable or mismatched, GitHub's Recent Deliveries shows the failure code — that is the first place to look.

05 / Steps 5–6 — Wire Both Sides

05 — GitHub Webhook

Repo → Settings → Webhooks → Add webhook → Payload URL http://<jenkins-url>/github-webhook/ (trailing slash matters) → application/json → push events → Save → confirm green checkmark (initial ping delivered). If it exists and is green, reuse it.

06 — Jenkins trigger

Job → Configure → Build Triggers → GitHub hook trigger for GITScm polling → enable → Save.

WHY THIS EXISTS

Without a webhook, Jenkins only learns about pushes when someone clicks Build Now or a poll discovers them late. The webhook moves discovery from minutes/hours to seconds.

06 / Step 7 — End-to-End Test

$ echo "<!-- trigger -->" >> index.html && git commit -am "trigger webhook" && git push # then watch Jenkins → Jenkins build history: new build starts automatically → Console Output: checkout pulled latest commit SHA

VERIFY — Jenkins build history shows an automatic build.

Console output confirms the checkout SHA matches the pushed commit. GitHub webhook Recent Deliveries shows 200. PASSED

GOTCHA

WSL / localhost Jenkins is invisible to GitHub. Webhooks require a public URL — use ngrok / localhost.run or a reverse proxy. Decide in Step 0. Branch mismatch (main vs master) also silently breaks checkout — confirm the real default branch.

PROOF — A file edit + push triggered a build without Build Now. The loop commit → webhook → build is closed. ● WEBHOOK PROVED

05 / Step 3 — Jenkinsfile (seven stages)

pipeline { agent any environment { IMAGE_NAME = "myusername/app" IMAGE_TAG = "build-${env.BUILD_NUMBER}" } stages { stage('Environment Setup') { steps { echo 'Loading environment...' } } stage('Code Checkout') { steps { checkout scm } } stage('Docker Build') { steps { sh "docker build -t ${IMAGE_NAME}:local ." } } stage('Authentication') { steps { withCredentials([usernamePassword(credentialsId: 'dockerhub-creds', usernameVariable: 'DOCKER_USER', passwordVariable: 'DOCKER_PASS')]) { sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin' } } } stage('Image Tagging') { steps { sh "docker tag ${IMAGE_NAME}:local ${IMAGE_NAME}:${IMAGE_TAG}" } } stage('Image Push') { steps { sh "docker push ${IMAGE_NAME}:${IMAGE_TAG}" } } stage('Application Deployment') { when { expression { return params.DEPLOY_TO_FLOCI == true } } steps { echo "Deploying ${IMAGE_NAME}:${IMAGE_TAG} into FLOCI..." } } } }

GOTCHA

Never hardcode the token in the Jenkinsfile. Use withCredentials. Prefer a scoped access token over the account password.

Lab 03

Multibranch · Branch as Job
03
MULTIBRANCH PIPELINE

One job, three branches, one Jenkinsfile. Branches are discovered, not configured — and when decides what runs where.

01 / What This Lab Proves

PROOF — A Multibranch Pipeline is a folder of branch jobs driven by branch discovery + Jenkinsfile on each branch. env.BRANCH_NAME makes one file behave as three pipelines. Deleting a branch orphans its job on next scan.

02 / Concept — Folder of Jobs

MAIN Jenkinsfile found → build main
DEV Jenkinsfile found → build dev
STG Jenkinsfile found + when(stg) runs stg

Parent job controls everything: Branch Sources, Filter by name (main dev stg), and Additional Behaviors. Individual branch items are not directly configurable — they inherit.

Lab 04

Reuse · Version Pin
04
SHARED LIBRARY

Copy-paste is not reuse. A pipeline library is a dependency: versioned, reviewed, rolled back. One Groovy class, two pipelines, one approval gate.

01 / What This Lab Proves

PROOF — A Global Pipeline Library (src/com/<you>/UatInput.groovy) exposes buildIsUatApproved() (checks tools/approved.txt) to both scripted and declarative pipelines via @Library('shared-library'). Changing the library changes all consumers — and reverting fixes them.

02 / Repo Layout (Jenkins expects this exactly)

(root) └── src/ └── com/ └── <yourname>/ └── UatInput.groovy → class UatInput { boolean buildIsUatApproved() } checks workspace file: tools/approved.txt → true / false

# UatInput.groovy — minimal logic package com.example class UatInput implements Serializable { boolean buildIsUatApproved() { return fileExists('tools/approved.txt') } }

WHY VERSION PIN MATTERS

Default version = master is a live dependency. Pin consumers with @Library('shared-library@main') or a tag when you want reproducible builds rather than latest.

Scripted + declarative

05 / Steps 3–4 — Scripted Pipeline

PIPELINE — New Item → Pipeline (shared-library-test-pipeline) → uncheck Groovy Sandbox.

Sandbox off avoids approval noise for this simple class (production: use In-process Script Approval instead).
@Library('shared-library') _ import com.example.UatInput def uatInput = new UatInput() println "Build is UAT approved: ${uatInput.buildIsUatApproved()}"

VERIFY — With tools/approved.txt present → true; without → false in Console Output.

06 / Step 5 — Declarative Pipeline (when gate)

@Library('shared-library') _ import com.example.UatInput def uatInput = new UatInput() pipeline { agent any stages { stage('Run only if approval exists') { when { expression { return uatInput.buildIsUatApproved() } } steps { echo 'The build has been approved.' } } } }

EXPECT — Stage runs when approved.txt exists; skipped without failing the build when absent.

07 / Step 6 — End-to-End Validation

  • With file → PASSED stage executed.
  • Without file → SKIPPED — no output from inside when (not a failure).
  • Break the library → both consumers break; revert → both fix (proves shared dependency).
  • Trouble: not found → name/version mismatch; sandbox blocks → approve signature or restrict source.
PROOF — Reuse without copy-paste, gated by workspace state, consumed from two pipeline styles. ● REUSE PROVED

05 / Interview Checks

WHY DOES /github-webhook/ NEED A TRAILING SLASH?

Jenkins registers the endpoint with the slash. Without it GitHub receives a redirect that is not treated as a successful delivery.

MULTIBRANCH VS WEBHOOK?

Multibranch discovers branches by scanning; webhooks notify eagerly. Labs 01 and 03 show both — webhook for immediate trigger, scan for air-gapped/periodic discovery.

WHY withCredentials?

It injects the secret as an env var at runtime, masks it in logs, and avoids storing it in the Jenkinsfile or Git history.

SHARED LIBRARY VERSION PIN?

@Library('lib@tag') freezes the consumer. Unpinned master tracks latest — useful for shared standards, risky for reproducible builds.
