CI/CD SYSTEMS SHARED LIBRARIES

01 / Reusable Pipeline Logic

As pipeline complexity grows, duplicating Groovy logic across dozens of Jenkinsfiles creates a maintenance nightmare. A Shared Library allows you to store versioned Groovy classes in a standard Git repository and import them into any pipeline.

01 SOURCE Groovy repository PASSED
02 REGISTER Jenkins Config PASSED
03 IMPORT @Library('lib') _ RUNNING
04 INSTANTIATE new UatInput() WAITING
05 EXECUTE Conditional run WAITING

WHAT

A Git repository containing Groovy code that Jenkins dynamically downloads and makes available to pipelines via an import statement.

WHY

To enforce DRY (Don't Repeat Yourself) principles in CI/CD. Updates to shared logic propagate to all pipelines without modifying individual Jenkinsfiles.

WHEN

When multiple pipelines share common logic: deployment steps, approval gates, metric parsing, or custom build wrappers.

WHAT CHANGES

Pipelines become thinner. Complex business logic is abstracted into testable Groovy classes, moving Jenkins configuration closer to standard software engineering.

WHY THIS EXISTS

Without shared libraries, organizations end up with hundreds of bloated Jenkinsfiles that are impossible to update. A shared library transforms CI/CD logic into a versioned, testable software dependency.

02 / Repository Architecture

Jenkins expects a specific directory structure for shared libraries. Groovy classes must reside in the src/ directory, following standard Java package naming conventions.

GOTCHA

The package path in the file (package com.yourname) must exactly match the folder structure (src/com/yourname/). A mismatch will result in a ClassNotFoundException during pipeline execution.

03 / Jenkins Registration

Before a pipeline can import the library, Jenkins must be aware of its existence. Register the library globally so it is available to all jobs without per-job configuration.

System Configuration

Manage Jenkins -> Configure System Global Pipeline Libraries -> Add > Library Name: shared-library > Default Version: master > Retrieval Method: Modern SCM > SCM: GitHub > Project Repository: https://github.com/user/repo.git Click "Validate" to test connection.

GOTCHA

By default, shared library scripts run in the Groovy Sandbox. If your custom class uses standard Java I/O (like new File()), you must uncheck "Use Groovy Sandbox" in the Pipeline job configuration, or explicitly approve the method signatures in Manage Jenkins -> In-process Script Approval.

INTERVIEW CHECK

Q: What is the difference between Global Pipeline Libraries and Automatic Pipeline Libraries?

A: Global libraries are available to any pipeline but must be explicitly imported via @Library. Automatic libraries are implicitly imported into all pipelines without the annotation, which is convenient but can hide dependencies.

CI/CD SYSTEMS SCRIPTED EXECUTION

04 / Scripted Pipeline Usage

Import the library into a scripted pipeline using the @Library annotation. Instantiate the class and call its methods to evaluate workspace state.

@Library('shared-library') _ import com.yourname.UatInput node { stage('Check Approval') { def uatInput = new UatInput() def isApproved = uatInput.buildIsUatApproved() println "Build is UAT approved: ${isApproved}" } }

Execution Result (File Present)

COMMAND

$ touch tools/approved.txt $ build now

RESULT

[Pipeline] stage [Pipeline] { (Check Approval) Build is UAT approved: true [Pipeline] }

WHY IT MATTERS

The underscore _ in @Library('shared-library') _ is required when importing classes. It tells Jenkins to import the library but not automatically run any global variables or scripts, only making the classes available for explicit instantiation.

CI/CD SYSTEMS DECLARATIVE EXECUTION

05 / Declarative & Conditionals

In declarative pipelines, the imported class can be used inside a when block to conditionally skip or execute stages based on workspace state.

@Library('shared-library') _ import com.yourname.UatInput def uatInput = new UatInput() pipeline { agent any stages { stage('Deploy to Prod') { when { expression { return uatInput.buildIsUatApproved() } } steps { echo 'Deployment approved.' } } } }

State Transition

APPROVED
tools/approved.txt exists RUN STAGE
UNAPPROVED
tools/approved.txt missing SKIP STAGE

GOTCHA

The when directive is evaluated before the agent is allocated for the stage if beforeAgent true is not set. If your Groovy class reads files from the workspace, ensure the agent is checked out first, or evaluate the condition inside a script block within the steps.

INTERVIEW CHECK

Q: Why disable the Groovy Sandbox for shared libraries?

A: The sandbox limits dangerous operations (like file system access) for untrusted scripts. Shared libraries are considered trusted code. Disabling the sandbox allows the library to perform necessary system operations, though it requires strict review of the library code.
